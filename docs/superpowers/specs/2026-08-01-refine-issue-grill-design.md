# refine-issue への grill 型尋問の導入 — 設計

## 目的

`shared/skills/refine-issue/SKILL.md` の Phase 3 を、チェックリスト穴埋め型から grill 型尋問（前提への挑戦・推奨回答つき質問・決定木・台帳ベースの収束）に置き換える。Issue の前提そのものを疑い、「このIssueだけ読めば実装に着手できる」に加えて「この Issue は解くべき問題か」まで検証された状態を作る。

## スコープ

- 対象ファイル: `shared/skills/refine-issue/SKILL.md` のみ（1ファイル完結。補助ファイル分離はしない）
- Phase 1（取得・分析）/ Phase 2（コードベース調査）/ Phase 4（Issue更新）の骨格は維持
- grill の独立スキル化はしない（将来、計画・設計の grill 需要が出たら抽出を検討）

## 変更内容

### 1. Phase 3 を grill 型尋問に置換

種別ごとの決定木を定義し、上流が確定するまで下流を聞かない。

- 機能系: 前提・価値（そもそも正しい問題か、代替案、非ゴール）→ ゴール・完了条件 → スコープ → アプローチ → テスト観点
- 不具合系: 前提・価値 → 再現性 → 原因分析 → 影響範囲 → スコープ → テスト観点
- 運用系: 前提・価値 → 対象特定 → タスク一覧 → 検証方法 → ロールバック

既存のカテゴリ別チェックリストは削除せず、各枝での「聞き漏らし確認用の網羅表」に位置付けを変える。

### 2. 質問形式（grill フォーマット）

1問（同一枝なら最大3問）ずつ、必ず以下を添える:

- 現在の理解（Issue 本文とコード調査からの要約）
- 質問 + なぜ重要か + これで何が決まるか
- 推奨回答（コードベース調査の根拠つき。AskUserQuestion の第一選択肢に Recommended として置く）

「調べれば分かることは聞かない」を明文化する。リポジトリ・ログ・git 履歴で答えが取れる質問は調査して証拠を提示し、判断だけを聞く。

### 3. 収束条件: ラウンド上限廃止 + 共有理解台帳

「最大3問×3ラウンド」を撤廃。各ラウンド末尾で台帳を提示する:

```
確定: ...
未解決: ...
前提(未検証): ...
リスク: ...
```

終了条件は「実装に影響する未解決事項が尽きた」または「ユーザーが打ち切りを指示」。充足済み Issue なら質問数は自然に減る（軽い Issue への配慮は発動条件ではなく質問数の自然減で担保）。

### 4. 前提崩壊時の出口（新設）

尋問中に Issue の前提が崩れた場合、通常フローを中断して選択肢を提示し、承認後に実行する:

1. クローズ + 再起票 — 経緯コメントを付けてクローズし、新 Issue は create-issue スキルへ委譲
2. 再定義して更新 — 新しい前提で本文を書き直し Phase 4 へ
3. そのまま続行 — ユーザーが前提を維持すると判断した場合

### 5. Phase 4 への反映

- 台帳の「確定」を Issue 本文へ反映する
- 「前提(未検証)」「リスク」が残る場合は本文に「未確定事項」セクションとして明記する
- frontmatter の description は動作説明のみ更新（前提挑戦の性格を反映。トリガー追加は不要 — 常時 grill 化のため）

## 決定事項（対話で確定）

- grill 要素は4つすべて採用: 前提への挑戦 / 質問の形式強化 / 決定木・依存順 / 収束条件の緩和
- 発動条件: 常時 grill 型（モード分岐なし）
- 前提崩壊時: クローズ/再定義まで提案し、承認後に実行まで踏み込む
