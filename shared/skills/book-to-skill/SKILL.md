# 書籍のスキル化

書籍を読み込み、「エージェントの行動を変える知識」だけを抽出して SKILL.md に圧縮する。

## 不変条件

- **PDF本文を正とする**。モデル知識は補正・整理に使ってよいが、書籍と矛盾したら書籍に従う
- **原文を引用せず要約再構成する**（著作権）。図表も構造だけを再表現する
- **出典明記**: スキル冒頭に書名・著者、項目ごとに出典タグ（例: `[CFH]`）。増補時は既存構造を保ち新タグで区別する
- 範囲は読解〜description設計まで。デプロイ・発火テストは行わない

## 手順

### 1. 読解 — 章別サブエージェント並列抽出

目次を読んで章リストとページ範囲を確定し、章ごとにサブエージェントを並列起動する。
各サブエージェントへの指示:

- 担当ページ範囲を Read（PDFは1回20ページまで、複数回に分ける）
- **抽出対象**: 規律・閾値・判断基準・アンチパターン（症状/原因/解決策）・手順・チェックリスト・比較表
- **対象外**: 演習問題・歴史的経緯・著者の逸話・コード例の逐次解説
- 出力: 項目ごとに「名前 / 一行要旨 / 詳細（表現可能なら表）」のリスト

### 2. 判断 — 新規 / 分割 / 増補

既存スキル一覧（`shared/skills/*/SKILL.md` の description）と領分を照合し、
**独立トリガーがあるか**を第一軸に判断する:

| 状況 | 判断 |
|---|---|
| 既存スキルと同じ場面で発火すべき内容 | 既存スキルへ増補 |
| 1冊の中に独立した発火場面が複数（例: DB設計とSQLクエリ） | 複数スキルに分割 |
| 上記以外 | 新規1スキル |

ハブスキルからの呼び出し都合だけでは分割しない。

### 3. 骨子案ゲート — ユーザー承認

以下を提示し、承認を得てから執筆に入る:

- スキル名（または増補先スキル名）と判断理由
- 収載目録（章 → 収載項目）
- **捨てた章とその理由**（選別の見落としを検査可能にする）

### 4. 執筆

- SKILL.md は要約層として150行以内目安。全項目を一覧表・チェックリストで引ける状態にする
- 要約層に収まらない詳細（各項目の症状・解決策の解説など）は補助ファイルへ分離し、
  SKILL.md から「該当が疑われた項目だけ読む」形で参照する（例: rdb-design の `ANTIPATTERNS.md`）
- **増補時**: 増補先の既存構成に従う（補助ファイル持ちのスキルなら該当補助ファイルへ追記する）
- **書籍の章立てを捨て、実用の構造へ再編する**: 基本ルール → 原則 → テクニック表 → アンチパターン → チェックリスト → 関連スキル（書籍の性質に応じて取捨）
- 同型の項目が並ぶものは表に圧縮する
- チェックリストは「執筆・レビュー時に上から確認できる問い」の形で書く

### 5. description 設計

- スキルの内容1〜2行 + トリガー語の列挙。トリガーはユーザーの言い回し・症状ベースで書く（「〜して」「〜がおかしい」）
- 隣接スキルがあれば領分宣言を入れる（例: 「SQLクエリの問題は sql-query-antipatterns の領分」）
- 手順の要約を description に書かない（本文を読まず description だけで動く事故を防ぐ）

## 完了報告

次アクションとして `./scripts/deploy.sh` の実行と `claude -p` での発火テストを一行で案内する。
