# 見直したい語と構文

AI生成文で目につく語と構文、その言い換え候補の一覧。置換表ではない。言い換えてよいのは、原文と資料から見て、意味の広さ・強さ・対象範囲が元と同じになるときだけである。同じと言い切れないなら元の語を残す。一覧にあることだけを理由に、自然な表現や実際の検証を表す語を変えない。

## 1. 比喩として使われる動詞

出来事や技術的な操作を比喩で言っている箇所は、ふだんの動詞に直す。比喩に込められていた含み（「地味に」の目立たないが確かな感じ、「〜てしまった」の後悔）は別の言葉で残す。定着した慣用句（骨が折れる、手を焼く、目から鱗が落ちる）は直さない。

| 動詞 | 見直したい用例 | 言い換え候補と注意 |
|---|---|---|
| 倒す | 「安全側に倒す」「残さない側に倒す」 | 「安全を優先する」「除外する」「〜の扱いにそろえる」 |
| 効く | 「地味に効いてくる」 | 「目立たないが役に立つ」「じわじわ助けになる」 |
| 溶かす | 「丸一日溶かした」 | 「丸一日かかってしまった」（後悔の含みを残す） |
| 潰す | 「1つずつ潰す」 | 「1つずつ直す」「解決する」 |
| 壊れる | 「データが静かに壊れる」「設計が壊れる」 | データやシステムには「おかしくなる」「使えなくなる」。「整合性が失われる」と書くのは整合性の話だと前後から明らかなときだけ。機械や身体の文字どおりの「壊れる」は残す |
| 静かに / 黙って | 「黙って無視される」 | 「気づかないうちに」「知らないうちに」。「エラーを出さずに」「通知なく」と書くのは、エラーや通知が出ないと原文から分かるときだけ |
| 踏み込む | 「〜まで踏み込んで」 | 「詳しく調べる」「掘り下げる」 |
| 沈黙する | 「サーバーが沈黙する」 | 「応答しない」。終了したか、通知が出たかは原文から分かるときだけ書く |
| 収斂する | 「その価格帯に収斂した」 | 「落ち着いた」「決まった」 |
| 添える | 「経路が代わりに添える」 | 「つける」「渡す」。付け足すのか渡すのかが決まらないなら元の語を残す |

## 2. 英語を直訳した構文

| 元の英語 | 直訳した日本語 | 自然な日本語 |
|---|---|---|
| the moment ... | 「保存した瞬間に」 | 「保存するとすぐに」「保存した時点で」 |
| silently fail | 「静かに失敗する」 | 「気づかないうちに失敗する」 |
| single source of truth | 「〜を正本にする」 | 「原文」「比較の基準」「参照元」など指す役割で書く。唯一の参照元だと明示されているなら、その限定を保つ |
| load-bearing | 「構造を支える」「耐力のある」 | 「欠かせない」「外せない」 |
| point to / suggest | 「〜を示唆している」 | 「〜を表している」「〜と考えられる」。言い切りの強さを保って選ぶ |
| delve into | 「深く分け入る」 | 「詳しく調べる」 |
| count | 「何を数え、いくつなら OK か」 | 「何を測り、どの値なら合格か」 |
| downstream | 「下流の読み手」 | 「後の工程で読む人」 |
| bet | 「この設計に賭ける」 | 「この設計で決め打ちする」「この見立てで進める」 |
| cheap / expensive | 「安い実験」「高価な変更」 | 「小さく試す」「時間がかかる変更」「取り返しのつかない変更」 |
| survive | 「仮説が生き残る」 | 「仮説が当たる」「外れない」 |
| open (a skill) | 「スキルを開く」 | 「スキルを使う」「手順を通す」 |
| behind a flag | 「フラグの裏で」 | 「フラグで無効にしたまま」 |
| em dash | 「重要な機能——とりわけ認証——は」 | 「重要な機能、特に認証は」。ダッシュを外して1文にすると前の理由や条件が後ろまで掛かるなら、2文に分ける |

専門的な対象を指す語は、その分野で定着した用語にする（状態を表す「旗」→「フラグ」、コードの「塊」→「ブロック」）。画面の項目名、コードの識別子、日常語として通じる語は変えない。何でもカタカナ語にしない。

## 3. AI生成文で増えた語

Qiita 記事7万件の調査（逆瀬川 2026）で、AI普及後に増えた語。増えたことは原因の証明ではない。原文でその語が担う意味と強さを確かめ、同じと言えないなら残す。

| 分類 | 語 | 言い換え候補 |
|---|---|---|
| 障害・失敗の比喩 | 事故、落とし穴、破綻、実害、素通り | 「思わぬ失敗」「見落としやすい点」「うまくいかなくなる」「実際の困りごと」「気づかず通る」。「破綻」を「問題がある」にすると強さが落ちる |
| 確認の比喩 | 実測、照合、突き合わせる、取り違える | 「実際に測った値」「照らし合わせる」「見比べる」「順序を間違える」。実際に測った・照合した事実を表しているなら残す |
| 役割・位置の比喩 | 入口、土台、核心、主役、構図、線引き | 「手始め」「基本」「いちばん肝心なところ」「中心」「全体の関係」。「線引き」は何を区別するかを書く |
| 評価の定型 | 既定、別物、定番、定石、桁違い | 「もともとの設定」「まったく違うもの」「よく使われるもの」「いつものやり方」「はるかに大きい」 |

## 4. 体験を大げさに見せる熟語

日常の体験や小さな技術判断を、難しい熟語で語らない。

- 見直したい語: 真理、真実、宿命、境地、極致、究極、虚飾、美学、深淵、禁欲的、冷徹、凝縮、結晶
- 例: 「日常の喧騒という虚飾を剥ぎ取った時、この道具の真実が見えてくる」→「日々の忙しさから離れたとき、この道具の本当の良さが見えてくる」
- 元にない教訓や固有名詞を足さない

## 5. 具体に見えて意味が曖昧な語

| 分類 | 語 | 直し方 |
|---|---|---|
| 質感を装う語 | 手触り、肌感、温度感、熱量、血の通った、泥臭い | 原文から分かる事実で書く（「手触り感を確認する」→「使い勝手を確認する」）。分からなければ同じ幅のふだんの言葉にする |
| 理解を曖昧に言う語 | 解像度を上げる、腹落ち、メンタルモデル | 指す考えを原文の範囲で書く（「課題の解像度を上げる」→「課題を詳しく整理する」）。定義された用語は残す |
| 評価を装う語 | 本質的な、地に足のついた、等身大 | 空疎な修飾なら削る。「本質」が文の論点そのものなら、別の概念にすり替えず残すか「いちばん肝心な点」にする |
| 役割を大げさに呼ぶ語 | ルールを指す「契約」、原文を指す「正本」 | 「ルール」「方針」「原文」「比較の基準」。取引の契約、正式な文書を区別する正本、定義された用語は残す |
| 指す内容が曖昧な名詞 | 書き方を指す「仕組み」、何を区別するか不明な「境界」 | 何をするか、何を区別するかを書く。分からないなら語は残し、「境界を守れば防げる」のような条件付きの主張も強さのまま本文に残して確かめる。数学の境界や境界値は残す |
| 未定義の造語 | 「意思決定OS」のような比喩の命名 | ふだんの言葉で機能を書く |

## 6. 定型の前置きと結び

語の形でなく働きで判断する。著者が実際に勧めている結びは、定型に似ていても残す。

| 分類 | 表現 | 直し方 |
|---|---|---|
| 前置き | 重要なのは、結論から言うと、正直に言うと、ここで注目すべきは | 前置きだけ削り、評価は述語に移す。比較から方針へ移る「結論として」のように、つながりを担う語は残す |
| 文末の付け足し | 〜というわけです、〜に他なりません、面白いのはここです | 原文の説明・評価・推量を、その強さのまま書く |
| 定型の結び | いかがでしたでしょうか、ぜひ試してみてください、参考になれば幸いです | 削り、本文の自然な結びで終える。削った穴を読者の感情で埋めない |
| 読了効果の付け足し | 「これらを理解すれば業務効率が飛躍的に向上します」 | 原文に根拠がなければ削る |
