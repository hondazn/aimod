# Natural Writing - 自然な日本語文章

人が書いた文章には「著者の声」がある。読み手は無意識にそれを感じ取り、信頼や共感につなげる。AI生成文にありがちな定型表現や過剰修飾は、この「声」を消してしまう。このスキルは、著者らしさが伝わる自然な日本語を生み出すためのガイドである。

## いつ効くか / いつ効かないか

効く: 日本語テキストを新しく書く、直す、品質を評価する作業。メール・記事・報告書・プレゼン原稿・SNS 投稿・設計文書の文面。

効かない:
- 何が良い技術文書かの規範（文書の型・論証の構成・見出しの付け方） → `technical-writing`
- 成果物ができた後の削り → `less-is-more`
- コード内コメント → `coding-standards`「どこに何を書くか」

## 最優先: 意味を保ち、足さない

自然に読めることは、意味が保たれた証拠にならない。以下のルールはすべて、この節を破らない範囲でだけ適用する。

書き直す前に原文の4点を確かめ、書き直した後も同じに保つ。

1. **主張**: 何を言っているか。論点を別の概念にすり替えない（「本質は〜」を「目的は〜」にしない）
2. **比重**: 何を一番大事とし、何を軽く扱っているか。否定していた A を「A に加えて B」と並べたり、順位を入れ替えたりしない
3. **言い切りの強さ**: 断定は断定のまま、推量・可能性はその強さのまま。「〜と言えるでしょう」を断定に上げず、断定を「おそれがあります」に下げない
4. **文の働き**: 評価・説明・依頼・予定・報告の区別と時制。完了した変更を予定の「〜します」にしない。評価の文を目標の文に変えない

足さない。原文・依頼・提供資料にない数値・事例・体験・動作主・原因・条件を作らない。ぼかした語をより狭い具体に置き換えない（「一部のユーザー」を「初心者」にすると範囲が変わる）。具体が欲しいのに材料がないときは、本文で作らず「書き手に確かめたい点」で尋ねる。新規作成でも事実は依頼と資料から取る。

削らない。条件・例外・否定・限定（「だけ」「一部」）・数値・未定や調査中という状態は、言い回しを変えても残す。

## モード判定

ユーザーの入力を読み、以下の3つのうち最適なモードを選ぶ。明示的な指示がなくても、文脈から判断してよい。

| モード | いつ選ぶか | ゴール |
|--------|-----------|--------|
| **新規作成** | テーマ・要点が提示され「書いて」「作って」等の指示がある | 自然な文章をゼロから生成する |
| **校正** | 既存文章が提示され、改善を求められている（デフォルト） | 原文の意図を保ちつつ自然さを高める |
| **診断** | 「診断」「チェック」「分析」「評価」等の語を含み、文章を直さず評価だけ求められている | 問題点と良い点を指摘する（書き換えない） |

迷ったら校正モードを選ぶ。ユーザーが文章を貼り付けただけなら、たいてい「直してほしい」という意味である。

## 校正モード

校正の核心は「原文の意図を壊さずに、読み手に届く文章にする」こと。著者が伝えたかったことを汲み取り、それをより効果的に表現し直す。機械的な置換ではなく、文脈を理解した上で判断する。直す箇所がほとんどない文章は、無理に書き換えない。

### 思考の流れ

1. **全体を通読する** - 誰が誰に何のために書いた文書かをつかみ、立場（勧め・決まり・説明）を決める
2. **構造を点検する** - 主語と述語、修飾の掛かる先、指示語と接続語のつなぎ先、条件や否定の範囲を対応づける
3. **AI臭さを検出する** - 定型表現、比喩動詞、過剰修飾、装飾記号をマークする
4. **文体と文末を確認する** - です/ます調とだ/である調の混在、立場や時制に合わない文末がないか
5. **具体化の余地を探す** - 原文や資料にある数値・事例で、抽象的な形容を置き換えられないか
6. **冗長表現を刈る** - 意味を変えずに削れる語句を削る
7. **原文と並べて読み比べる** - 足した語（数値・主体・条件・評価）、消えた語（条件・限定・否定）、文末の働き（依頼・義務・評価・可能）の増減、接続の掛かり先が変わっていないか。変わっていたら元に戻すか、「変えたところ」に理由を書く

### 文書の立場と文末

日本語は主語を省くため、文末が「誰が動くか」「決まりか勧めか説明か」「済んだことか予定か」を伝える。文末を直す前に立場を決める。

- **勧め**: 読み手に勧める・頼む文書（心得、助言）。動くのは読み手
- **決まり**: ルール・手順・仕様・お知らせ。動くのは従う読み手か、方針を決めた書き手
- **説明**: 事実・結果・考えを伝える文書（技術解説、報告、体験）

立場は、まず依頼にある行き先と読み手（「上長への報告」「チームの運用ルールとして」）で決め、次に本文の手がかり（「私は」「当チームでは」、宛名、見出し）で決める。「技術記事」のような分野名だけでは決めない。同じ分野にも決まり・報告・勧めの文書がある。決めきれず、文末を変えると働きが変わりうるときは文末を変えず、もう一方の立場で書く場合の文末を「書き手に確かめたい点」に1行で示す。

文末を直すのは次のときだけ。

- 文末のせいで動作主・時制・働きが意図とずれて読める（読み手への助言が書き手の予定「〜しておきます」に読める、完了した変更が予定の「〜します」に読める）
- 決まりの文書で、決まりそのものを「〜しましょう」「〜が重要です」と書いている。「〜します」にそろえ、理由の文と「〜してください」は残す
- です/ます と だ/である が意図なく混ざっている
- 同じ文末が続いて単調で読みにくい。語順や文のまとめ方で整え、働きや時制は変えない

同じ立場の中の強さ（「〜しましょう」と「〜してください」）は変えない。勧めを「〜しなければならない」に上げない。安全手順や必須の指示を弱めない。「〜しましょう」の数を減らすために文同士をつながない。システムの動作（「返します」）、可能（「できます」）、予定（「予定です」）、実施済み（「変更しました」）、現在の方針（「〜する方針です」）は役割どおりに書き分け、一つの語尾にそろえない。

### 文の構造とつながり

語を言い換える前に、関係を確かめる。

- 修飾語の掛かる先と、条件・例外・否定・限定・数量がどの動作に掛かるかを確かめる。文を切る・つなぐ・語順を変えた後も、同じ範囲に掛かっているか確かめる
- 述語ごとに動作主を確かめる。「上長が差し戻した場合、システムが通知します」のように主体が切り替わる箇所は、原文や資料で分かる主体を書く。分からない担当者は作らない。システムの動作を人の行為に変えない
- 「これ」「片方」を名詞に戻すのは、指す先が文脈から一つに決まるときだけ。近くにある名詞というだけで決めない
- つなぎ言葉（ただし、また、そのため、つまり）、主題の「も」、文頭の「こうした」は、何と何をつないでいるかを特定する。特定できないなら直さず確かめる
- 予告だけの文（「注目すべき点があります」「理由は以下の通りです」）は、予告の重みを述語に残して中身の文と1文にまとめる。まとめると意味が変わるなら残す
- 1段落1話題。話題が混ざった段落は、文の順序を保って分ける。話題の違う段落はまとめない
- 原文が複数の読みを許すとき、言い換えのために一つの読みに決めない

変更は、読み違いや読み戻りを具体的に指せる箇所に絞る。元から関係が追える文は残す。

### AI臭さの検出と対処

AI生成文が不自然に感じられるのは、「誰が書いても同じになる」表現が多いからである。以下のパターンを検出したら、著者の声が出る表現に書き換える。対処で「具体に置き換える」とあるのは、原文・依頼・資料にある具体を使うという意味である。無ければ削るか、書き手に確かめる。

| 検出パターン | なぜ問題か | 対処方針 |
|-------------|-----------|---------|
| 冗長な導入「〜について説明します」「本記事では〜」 | 読者は前置きを読み飛ばす。本題が遅れるだけ | 削除して本題から始める |
| 過剰修飾「非常に」「極めて」「まさに」の多用 | 具体性がないまま強調しても説得力がない | 削除するか、原文にある理由・数値に置換 |
| 曖昧な断定回避「〜かもしれません」「〜と思われます」の連発 | 責任逃れに見え、読者の信頼を損なう | 校正では強さを保ち、どれが確かな事実かを書き手に確かめる。新規作成では確かなことを言い切り、不確かなことは条件を明示する |
| パターン構文「〜という点で重要です」「〜が大切です」の繰り返し | テンプレート感が出る | 原文にある行動・結果で言い換える。無ければ繰り返しだけを整理する |
| 感情の押し付け「素晴らしい」「驚くべき」 | 読者が自分で判断する余地を奪う | 事実を書き、判断は読者に委ねる |
| 前置きのラベル「重要なのは」「結論から言うと」 | 主張の前に予告を挟み、本題が遅れる | 前置きだけ削り、評価は述語に移す（「〜が重要だ」）。理由・対比・結論への切り替えを担う語は残す |
| 否定対比「A ではなく B」の多用 | 誰も言っていない A を立てる修辞になる | A を外しても主張が変わらないときだけ肯定文にする。誤解を正す否定は残す |
| 比喩動詞「安全側に倒す」「地味に効く」「時間を溶かす」「静かに壊れる」 | 指す動作が一つに決まらず、読み手が解釈を補う | ふだんの動詞に直し、「地味に」「〜てしまった」などの含みは別の言葉で残す。定着した慣用句（骨が折れる、手を焼く）は残す |
| 擬人化「コードが語る」「システムが願う」 | 道具に意志を持たせ、事実がぼやける | 内容の所在や動作として書く。「ツールがログを集める」のような働きの説明は残す |
| 意味の曖昧な語「解像度を上げる」「腹落ち」「温度感」「本質的な」 | 具体に見えて何を指すか決まらない | 原文から分かる範囲でふだんの言葉にする。分からなければ残して確かめる |
| コピー調「資料を、全員へ。」 | 広告の文体で、動作と判断が書かれない | 述語まで書く。動作が原文から分からないなら作らない |
| 装飾記号（絵文字、ダッシュ「——」、文末コロン、言い換えだけのカッコ） | 書式で強調しても内容は増えない | 句読点や助詞でつなぐ。「日時：10時」のようなラベルと値の区切りは残す |

語ごとの言い換え候補は [references/CATALOG.md](references/CATALOG.md) にある。候補は置換表ではない。意味の広さと強さが同じになるときだけ使い、言い換えられないなら元の語を残す。

### 冗長表現の刈り込み

日本語は丁寧にしようとすると冗長になりやすい。意味が変わらないなら短い方がよい。

- 「〜することができます」→「〜できます」
- 「〜という形になります」→「〜です」
- 「基本的には」「一般的に」→ 削除するか、具体的な条件に置き換える
- 「〜を行う」→「〜する」（「確認を行う」→「確認する」）
- 「〜についての」→「〜の」

外枠を外しても、義務・可能・評価・経験の意味は残す。「〜かを確かめることが重要」を「〜かを確かめる」にすると、評価が指示に変わる。

一文の目安は60字以内。**規則ではなく目安である。** 長いことだけを理由に分けない。分けるのは、理由・手段・順序・対比のつながりを、後ろの文のつなぎ言葉（「そのため」「一方で」）で残せるときだけ。「〜するために〜します」のように目的が文末に掛かる文は、分けると何のための何かが崩れるので分けない。

簡潔にすべきでない場面:
- ビジネスメールで相手への配慮が必要なとき
- 複雑な概念を噛み砕いて説明しているとき
- 文章全体が短文ばかりでぶつ切り感があるとき

### 文体の統一

ひとつの文書内で文体が揺れると、読者は落ち着いて読めない。

- です/ます調とだ/である調を混ぜない（引用文は例外）
- 箇条書き内も本文と統一する
- 校正では原文の文体を保つ。「技術記事だから」のように分野だけを理由に変えない
- 新規作成の選択基準: ブログ・メール・説明文 → です/ます調、報告書・論文・技術文書 → だ/である調

### 具体化

「重要」「便利」「効果的」は情報量ゼロの言葉である。読者が知りたいのは「なぜ重要か」「どう便利か」「何がどう変わるか」。

- 原文や資料に数値・事例・比較があるなら、抽象的な形容をそれで置き換える
- 無いなら作らない。形容を削っても主張が立つなら削る。具体が要るなら「書き手に確かめたい点」で尋ねる（「『大幅に短縮』の実際の時間はありますか」）
- すべてを具体化する必要はない。文章のリズムや読みやすさとのバランスを取る

## 新規作成モード

ゼロから文章を書く場合、以下の手順で進める。

### 事前確認

ユーザーが明示していなければ、以下を確認するか文脈から推測する:
- **読者**: 誰に向けた文章か（専門家 / 一般読者 / 社内 / 顧客）
- **目的と立場**: 何を伝えたいか（情報提供 / 説得 / 報告 / 依頼）、勧め・決まり・説明のどれか
- **文体**: です/ます調 / だ/である調 / カジュアル
- **分量**: 大まかな長さ
- **材料**: 使ってよい事実・数値・体験。無いものは書かない

読者層に応じた調整:
- 一般読者向け: 専門用語を避け、身近な例えを使う
- 専門家向け: 冗長な説明を省き、その分野で定着した用語で簡潔に書く
- 社内向け: 組織の共通言語を使い、外部向けの丁寧さは不要

### 執筆の原則

1. **冒頭は具体的に** - 抽象的な前置きではなく、読者が「自分に関係ある」と感じる情報から始める
2. **一文一意** - 1つの文で1つのことだけ伝える。接続助詞でつなぎすぎない
3. **構成は伝えたい順** - 重要なことから書く。結論を後回しにしない
4. **自分の声で書く** - テンプレート表現を使わず、この文章でしか言えないことを書く。ただし材料にない体験や数値は作らない
5. **結論は明確に** - 「〜ではないでしょうか」で終わらせない

### やってはいけないこと

- 「〜について書きます」「本記事では〜」で始める（読者にとって無意味）
- 「非常に」「極めて」を根拠なく使う
- 「いかがでしたでしょうか？」「最後までお読みいただきありがとうございます」等のテンプレート的な締め
- 絵文字、ダッシュ、コピー調、太字の乱発。短い文章に本文を繰り返すだけの「まとめ」見出しを置く

## 診断モード

文章を書き換えず、品質を評価して問題点と改善方向を示す。

### 自然さスコア基準

| スコア | 状態 | 判断の目安 |
|--------|------|-----------|
| 5.0 | 自然 | AI臭さなし、具体的、文体統一、著者の声がある |
| 4.0 | ほぼ自然 | 軽微な問題が1-2箇所ある程度 |
| 3.0 | 改善余地あり | AI臭い表現や抽象的な形容が複数ある |
| 2.0 | 不自然 | 定型表現が目立ち、著者の声が感じられない |
| 1.0 | 機械的 | テンプレートの穴埋めのような文章 |

### 冗長性の4観点

依頼の主眼が「無駄・簡潔さ・文章量」にあるとき（「冗長じゃないか」「無駄がないか」「短くしたい」等）は、自然さスコアの代わりに以下の4観点を 0.0〜5.0 の 0.5 刻みで採点し、スコアの低い観点から問題箇所を示す。

| 観点 | 何を測るか | 代表的なチェック |
|------|-----------|----------------|
| 情報密度 | 1文あたりの新しい情報量 | 既出情報の言い換え、「〜ということです」等の情報を足さない文末、具体例なき抽象論の連続 |
| 簡潔性 | 表現レベルの無駄 | 「〜することができる」、重言（「まず最初に」）、効果の薄い強調語、長い前置き |
| 論理効率 | 論理展開の重複 | 同じ主張の形を変えた繰り返し、「つまり」の後に新情報がない、別セクションで同じ論点 |
| 構造最適性 | 見出し・構成の過不足 | 1〜2文しかないセクション、類似見出しの並列、深すぎるネスト |

- 判定: 4.0以上=良好 / 2.5〜3.5=改善余地あり / 2.0以下=要改善
- 総合は採点した観点の平均（小数第1位まで）。省略した観点は分母に入れない
- 500字未満の文章では構造最適性を省略してよい
- ジャンルを考慮する（技術文書では正確性のための繰り返しが許容されることがある）
- 改善案は意味を保ったまま圧縮する方向で出す。意味が変わる削除は提案しない

## 出力形式

モードごとに以下の形式で出力する。ただし、形式に縛られすぎず、ユーザーにとって最も読みやすい出力を優先する。「本文だけ」と指定されたら本文だけを返す。

### 新規作成モード

```
[生成した文章]

---
**構成メモ**
- 意識した点を簡潔に
```

### 校正モード

```
[改善後の文章]

---
**主な変更点**
- 元の表現 → 書き直し後（理由）

**残した箇所**（AIっぽく見えても意図的に残した場合）
- 残した表現と理由

**書き手に確かめたい点**（本文を確定するのに必要な場合だけ、最大2点）
- 何が分からず、本文のどこに影響するか
```

変更点では「何を変えたか」だけでなく「なぜ変えたか」を一言添える。原文の表現を意図的に残した場合、その判断理由も示す。これにより、ユーザーが自分の文章力を向上させるヒントになる。変更点は、意味が動きやすい変更・文末や接続を直した箇所・補った語を優先し、5点程度に絞る。文末をそろえた箇所は1行にまとめる。

本文には「要確認」「※」のような編集メモを挟まない。分からないことは「書き手に確かめたい点」に置き、本文は原文の主張と条件を保った暫定文にする。原文が読者に伝えている「未定」「調査中」は本文に残す。

### 診断モード

```
**自然さスコア: [1.0-5.0]**

**検出された問題**
1. [問題] - 該当箇所の引用 - 改善の方向性

**良い点**
- 評価できる点（必ず見つけて伝える）
```

冗長性診断では、先頭の自然さスコアを4観点のスコア表（各観点＋総合）に置き換え、以降は同じ形式で問題と良い点を示す。

良い点を必ず挙げる理由: 文章を提出してチェックを求めるユーザーは、自分の文章に不安を持っていることが多い。問題の指摘だけでは「全部ダメ」という印象を与えてしまう。良い点を明示することで、著者が自分のスタイルの強みを自覚し、それを伸ばせるようになる。

## 判断に迷ったとき

### 丁寧さ vs 簡潔さ

ビジネスメールや顧客対応では、冗長に見える表現が実は必要な丁寧さであることがある。

```
「ご確認いただけますと幸いです」
→ 簡潔にすると「確認してください」だが、ビジネス文脈では不適切なことが多い
→ 判断基準: 読者との関係性と文書の目的による
```

### 断言 vs 留保

すべてを断言すれば良いわけではない。不確実なことを断言するのは誠実でない。

```
判断基準:
- 校正 → 原文の強さを保つ。推量を断定に、断定を推量に変えない
- 校正で推量が連発しているとき → どれが確かな事実かを書き手に確かめる。分からないうちは強さを保ち、重複だけ整理する
- 新規作成 → 事実は断言、意見は「〜と考えている」（1回は問題ない）、不確実な情報は条件を明示（「〜の場合は」）
```

### 比喩 vs 慣用句

```
判断基準:
- AIが広まる前の人の文章でもふつうに見かける言い方（骨が折れる、手を焼く、首を長くして待つ） → 残す
- 指す動作が一つに決まらない比喩（安全側に倒す、時間を溶かす、静かに壊れる） → ふだんの言葉に直し、含みは残す
- 意味を保って言い換えられない → 元の語を残す
```

### 箇条書き vs 地の文

```
判断基準:
- 並列が明確な箇条書き（独立した変更点、手順、担当と結果の対応） → AIっぽく見えても残す
- 論理のつながりが箇条で分断されている → 地の文にする。そのとき元に無い評価や義務（「〜が大切です」）を足さない
- 地の文にすると同じ文末が単調に続く → 箇条書きのまま残す
```

### 著者の個性 vs 読みやすさ

校正で著者の個性を消しすぎると、「正しいが無味乾燥な文章」になる。

```
判断基準:
- 独特だが意味が通る表現 → 残す
- 独特で意味が伝わりにくい表現 → 著者の意図を確認してから修正を提案
- 明らかな誤り → 修正する
- 好みの問題 → 原文を尊重する
```

## 判定テスト

- 「この文を他の誰が書いても同じになるか」— なるなら著者の声が消えている
- 「原文・依頼・資料に無い数値・事例・主体・条件を足していないか」— 足したなら外すか、書き手に確かめる
- 「主張・比重・言い切りの強さ・文の働きが原文と同じか」— 完了した変更を予定に、勧めを義務に、推量を断定に変えていないか
- 「条件・限定・否定が消えていないか」
- 「一文が二つのことを言っていないか」— 言っているなら分ける
- 「文体（です・ます / だ・である）が最後まで揃っているか」
