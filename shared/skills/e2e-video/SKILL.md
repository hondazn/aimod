# E2E証跡動画

受け入れ基準の操作を実ブラウザで通し、**見て分かる証跡動画**としてPRに残す。

環境構築（使い捨てDB・シード・devサーバ）はプロジェクト固有で、正本はその
プロジェクトの runbook（例: `docs/ops/runbook-e2e.md`）。**先にその「まだ
できないこと」を読む。** runbook が無ければ、プロジェクトの開発手順から DB と
dev サーバの起動・シードを整えてから始める。

汎用部品は `scripts/` にある。`cursor.js`（疑似カーソル）、`helpers.mjs`
（間・滑らかスクロール・フラッシュ・解説パネル）、`scenario-template.mjs`（雛形）、
`to-mp4.sh`（変換）。相対パスはこのスキルの basedir 基準。

## 道具立て（毎回ここで詰まる）

**`playwright-core` も、使える `ffmpeg` も、対象プロジェクトに入っているとは
限らない。** 先に `package.json` を見て、無ければ以下で用意する。

| 要るもの          | 入手                                                                                                                                                                                                                                          |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `playwright-core` | 作業ディレクトリで `npm i --no-save playwright-core@latest`。プロジェクトの `node_modules` を symlink しても効かない（ESM は import 元のファイル位置で解決する）。**スクリプトごとその作業ディレクトリに置く**                                  |
| Chromium          | `~/.cache/ms-playwright/chromium-<番号>/chrome-linux64/chrome` に既にある。playwright-core が要求する番号とズレるので `chromium.launch({ executablePath })` で明示する。**ダウンロードは要らない**                                            |
| ffmpeg            | playwright 同梱の `ffmpeg-1011/ffmpeg-linux` は **libx264 も `-preset` も無い最小ビルド**で `to-mp4.sh` が落ちる。`pip install imageio-ffmpeg` して `FFMPEG_BIN=$(python3 -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())")` |

## 何を撮るか

受け入れ基準の操作をそのまま撮れるとは限らない。**変更が画面に直接出ない
ときは、周辺の退行しうる操作を撮る。** 基本形は 3 本:

1. **塞いだ側** — 拒否されるはずの操作が拒否される
2. **通る側** — 同じ対象に対して、権限のある側は通る（退行していない担保）
3. **逆側の本来の操作** — 塞ぎすぎていない担保

同じ対象（同じ受注など）を 1・2 で扱うと、3 本で 1 つの話になる。

## 手順

### 0. 前提の確認

- runbook の手順で使い捨てDBをシードし、devサーバを起動する。
  **録画の直前にシードし直す** — 入力欄へのタイプは追記型なので、残データが
  あると値が連結されて壊れる（例: `1200` → `12001200`）。
- DB を触る場合、接続先がローカルの使い捨てであることを確認する（クラウドに
  接触しない）。

### 1. シナリオを書く（1シナリオ1本）

`scripts/scenario-template.mjs` を複製する。原則:

- `recordVideo` の出力先は**実行ごとに空のディレクトリ**にする。古い webm が
  残っていると後の変換で混ざる。
- `goto` は初回だけ（ログイン画面など）。以後の画面遷移は**すべてクリック**で
  辿る。goto の瞬間移動は「クリックせずに飛んだ」ように見えて追えない。
- スクロールは `smoothScrollBy`（イージング付き）を使う。刻みホイールは
  カクつき、`scrollIntoView`（既定）は瞬間移動に見える。保存後のリダイレクト
  は頁頭に戻るアプリの実挙動なので、そこから滑らかに戻って確認する。
- 検証箇所では `flash()` で赤枠点滅させる。何を見ているかが伝わる。
- **各ステップの頭で `caption()` を出し、操作の前に `clearCaption()` で消す。**
  操作が写っていても、なぜそれを見ているかは画面から読めない。「① 業者側の
  画面を直接開こうとする」「→ 発注ポータルへ戻された」のように、動画だけを
  見た人が筋を追える文を置く。実際にこれで「解説があってわかりやすい」と
  評価されている。
- 目視用の間を置く（切替直後 ≒2秒、操作間 ≒0.7秒、結果画面 ≒3秒）。
  速すぎると人間が追えない。

### 2. 録画する

カーソル・波紋は `scripts/cursor.js` を `addInitScript` で入れる（headless
には実カーソルが写らないため）。録画ファイルの確定はコンテキスト close 時。

### 3. 検証する（公開前に必ず）

- 金額・保存状態など主張する値をフレーム抜き出しで目視する。
- DB突合: 画面の id → 同一行の値を DB から直接引く（別DBを見ていないことの
  裏付け）。
- カーソルの有無は赤ピクセル数で機械判定できる（`#e11d48` 付近の計数）。
- 入力の追記事故が無いか（録画前のシード漏れで既存値に連結されていないか）。

### 4. 公開する

- **PR を起票するときは `gh pr create --attach <mp4>`。** 起票してから
  コメントに添付し、本文を編集してコメント URL を貼る、という順にしない。
  証跡を CI で検査するプロジェクトは本文しか見ないので、コメントに貼った
  動画は無いのと同じ扱いになる。`--attach` は `pr create` / `pr comment` /
  `issue comment` にある（トップレベルには無い）。
- **添付できたか機械で確かめる。** `--attach` は一部だけ失敗しても PR を作る:
  `gh pr view <番号> --json body --jq '.body' | grep -c 'user-attachments/assets/'`
  が本数と一致するか見る。
- 差し替え時は古い動画コメントを消す（陳腐化防止）。残すのは最新1本。
- 描画形式の検証は `gh api markdown` でできる。ただし user-attachments の
  プレイヤー化はブラウザ側で行われるため、最終確認はPRページの目視。

変換は `scripts/to-mp4.sh`（H.264・`faststart` 付き）。ffmpeg が無ければ
`pip install imageio-ffmpeg` のバイナリを使う。

## 落とし穴（実測）

- `addInitScript` 実行時に `documentElement` が無い場合がある。末尾の append
  が例外で落ちると「波紋は出るが矢印が出ない」になる。マウス移動時に
  自己修復マウントすること（`cursor.js` 済み）。
- Noto Sans JP の Variable フォントは Thin が既定に選ばれて細字化する。
  static 体を使うこと。`.woff2` はこの環境の fontconfig が読めない。
  （このPC固有: `~/.config/fontconfig/fonts.conf` で Source Han Sans 優先済み）
- `![]()` に mp4 を入れると壊れた画像になる。`<video>` タグは除去される。
  動画の埋め込み再生は user-attachments 経由だけ。
- **SPA のクライアントサイド遷移（Inertia.js など）は `waitForLoadState` では
  待てない。** `waitForURL(/pattern/)` を挟む。挟まないと前の画面のまま操作して、
  静かに別のものを撮る。
- **ダイアログの裏の行を `flash()` しても写らない。** 保存後の状態を見せるときは
  ダイアログを閉じてから一覧の行を光らせる。

## 次のステップ
