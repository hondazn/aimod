# 計画を立てること

## ユーザー入力

```text
$ARGUMENTS
```

## このスキルの目的

問題を理解した後、解法の着想を得て実行可能な計画に落とし込む段階である。
このスキルのゴールは「最善の設計」ではなく「実行に移せる筋の通った計画」を得ること。

---

## 前提

問題定義（未知のもの・与えられているもの・条件）がすでにある状態を想定する。
なければ、まず問題定義を簡潔に整理してからこのスキルに入る。

---

## 進め方

### 1. 5つの戦略で解法の着想を得る

以下の戦略から状況に合うものを選び、**1つずつ**ユーザーと探索する。
各戦略について推奨案を添え、ユーザーが accept/modify/reject できるようにする。
コードベースを調べれば判断できるものは自分で調査する。

#### (1) 類似問題への帰着

同じ「未知のもの」を持つ既知の問題に帰着できないか探す。
— コードベース内の類似実装、チームが過去に解いた問題、既知のデザインパターン、ライブラリが提供する解法。

#### (2) 補助問題の導入

元の問題が直接解けないとき、より簡単な関連問題をまず解く。
— 条件の一部を外した簡易版、一つのケースだけ扱うプロトタイプ、ハードコードで動く最小版。

#### (3) 逆向きに考える

望む結果から逆算して、必要なステップを導き出す。
— 最終的な API の形から内部設計を逆算、テストを先に書いて実装を導く（TDD）、ユーザー操作から必要な状態遷移を逆引き。

#### (4) 問題を変形する

問題を別の形に言い換えることで、解法が見えることがある。
— 抽象度を上げる（一般化）、具体例に落とす（特殊化）、等価な別の問題に変換する、制約を緩めて上界を見る。

#### (5) 分割して征服する

問題を独立した部分問題に分解し、それぞれに解法を割り当てる。
— レイヤー分割、フェーズ分割（段階的リリース）、関心の分離、依存関係の少ない順に並べる。

### 2. 計画を検証する

- **条件を全て使ったか** — 問題定義の制約が計画に反映されているか
- **各ステップは実行可能か** — 曖昧なステップや飛躍が残っていないか
- **計画に書いたコマンドを実走したか** — 完了条件に使う検証コマンド（型検査・テスト等）に限らず、手順として書くコマンドはすべて計画段階で一度実行する。構文が通ることと実行できることは別で、未実走のコマンドは実行者のところで初めて落ちる。実走できないものは「未検証」と明示する。検証コマンドが現状で通らないなら、既存問題の扱い（スコープ追加 or 条件の限定）を計画に明記する
- **目視・主観の条件を測定に落としたか** — 「崩れていない」「はみ出していない」のような目視項目のうち、二値で判定できる性質（あふれ・重なり・要素の有無・順序）は測定値の比較に置き換える。主観に残すのは選好（好み・美しさ）だけにする
- **変更が壊すものを予見したか** — 変更対象リストには本体だけでなく、変更が壊す既存テストや追随が必要なスタブ・検証を含める
- **手順は実行主体の視点で完結しているか** — 実行者（エージェント・人）が暗黙の工程（push・認証・後片付け）を知らない前提で書き、最後のステップが「作業が外から見える状態」（push 済み・デプロイ済み・報告済み）に到達しているか

### 3. 計画を整理する

対話で得られた戦略と判断を、問題の性質に合った形で整理する。
形式は問わないが、以下の要素を含める:

- **意図** — 誰が・どんな場面で・なぜ使うか。依頼に明示があれば転記して「（明示）」、なければ推定して「（推定）」と付記する。条件を満たしつつ意図から逸れる実装を、後段のレビューで検出可能にする
- **採用した戦略と理由** — なぜその解き方を選んだか
- **ステップと順序の根拠** — 何をどの順でやるか、なぜその順序か
- **不確実性** — わかっていないこと、検証が必要なこと。完了条件には確度（依頼・実測から導いた「確定」か、自分の判断で置いた「推定」か）を付記する

## 次のステップ

計画がまとまったら、状況に応じて次のスキルへ引き継ぐ:

- **計画をコード構造（型・境界・データフロー）に落とす** → `/design-code`
- **計画を Issue として記録する** → `/create-issue`
- **実装に着手** → 完了後は `/git-commit` → `/create-pr` に繋ぐ

---

## 注意事項

- 計画は「実行に移せる」ことが最優先。完璧な設計より、動かして学べる計画を選ぶ
- 不確実性は隠さず明示する。見切り発車ではなく、意識的に受け入れる
- 全ての応答は日本語で行う
