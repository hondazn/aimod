# 探索範囲と現状優先

## 探索より先に現状を取る

transcript は書かれた時点の記録で、その後 revert されても内容は変わらない。`git` と `gh` は今の状態を直接返す。探索の前に現状を取ると、次の3つが同時に得られる。

- タグの検証材料（ブランチ、未コミット差分、PR の状態）
- 探索の窓（触っているブランチと PR から、読むべき期間が決まる）
- 探索が不要かの判定（ユーザーが状態を渡していれば、履歴を辿る理由がない）

履歴が要らないのではない。履歴は「なぜその状態になったか」を埋めるために読む。

## 読んでよい範囲

読む transcript は、`cwd` メタデータが作業中ワークスペースと完全一致するものに限る。別プロジェクトの会話には、そのプロジェクトの秘密・未公開の意思決定・無関係な個人情報が入る。探索の利便性のためにこの境界を広げない。

`find-transcripts.mjs` は JSONL の先頭 128KB の `cwd` だけを見て選別し、メッセージ本文は読まない。ワークスペースを指定しない実行はしない。

窓の既定は直近7日。ユーザーが明示した範囲が常に優先する。「全部見て」と言われたら全期間を対象にし、「全部」を黙って「直近N件」に縮めない。

## 対応ホスト

| ホスト | 置き場 | 対応 |
|---|---|---|
| Claude Code | `~/.claude/projects` | 対応 |
| Codex CLI | `~/.codex/sessions` | 対応 |
| Cursor | 独自形式 | 非対応 |
| opencode | 独自形式 | 非対応 |

Cursor と opencode の transcript を辿る経路を aimod は持たない。対象ホストの作業が話題なのに Claude / Codex の結果だけを返すと、空の結果が「作業なし」と読まれる。非対応であることをブリーフに1行書く。
