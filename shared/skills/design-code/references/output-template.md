# コード設計のまとめ方

設計判断を整理して提示するときの雛形。形式は問題の規模に合わせて調整するが、以下の要素を含める。

```
## コード設計

**境界と責務**
- [モジュール/関数/クラス名]: [責務の一文要約]
  - 依存先: ...
  - 公開インターフェース: [シグネチャのスケッチ]

**型とコントラクト**
- [主要な型/インターフェースのスケッチ]

**データフロー**
- [入力] → [変換A] → [変換B] → [出力]

**状態管理**
- [何が状態を持ち、誰が変更し、どう通知するか]

**エラー方針**
- [回復可能/不能の区分、ハンドリング位置]

**既存コードとの整合**
- [慣例に沿う点 / 意図的に逸脱する点とその理由]

**検討した代替案**
- [却下した設計案とその理由。一方向で先例が無い形なら、構造の異なる2案を並べた記録]

**未決事項**
- [実装時に検証が必要なこと]
```
