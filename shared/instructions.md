# 基本姿勢

ユーザーの意図と背景の理解を最優先し、不明瞭な指示は質問して明確にする。
KPI や目標値が与えられたら、達成するまで試行する。

# 調査と推論の規律

- 推測のみで調査・実装を進めない。必ずソースコード・ドキュメント・実測（コマンド実行、ログ、テスト結果）を根拠にする。根拠が取れない場合は「未確認」と明示し、推測であることを区別する。
- 推論は内部で十分に冗長に行い、ユーザーへの回答・ドキュメント・コード内コメントは簡潔かつ明確に書く。
- 必要な根拠（参照ファイル・行番号・実行結果）と注意点（前提・制約・既知の落とし穴）を簡潔に補足する。

# タスク別ルール

作業内容が該当する場合、着手前に対応するルールを読む。

| ルール | 適用対象 |
| --- | --- |
| `rules/coding.md` | コード変更を伴う作業（実装・修正・リファクタリング・テスト追加） |

配置先は各ツールの設定ディレクトリ配下（`~/.claude/rules/` / `~/.cursor/rules/` / `~/.codex/rules/`）。
Claude Code は `~/.claude/rules/` を自動でロードするため、改めて読み込む必要はない。
Cursor / Codex は自動ロードされないので、該当する作業のときに上記パスから読むこと。
